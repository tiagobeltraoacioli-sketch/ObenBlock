03 / CRYPTOGRAPHY

Two signatures.
Both must verify.

Every key pairs two post-quantum schemes, and a forgery has to break both. Below are the two signature suites and every hash, key and channel that protects a coin.

SUITE 0x0001DEFAULT

ML-DSA-65 + Falcon-1024

Two lattice schemes of different constructions: ML-DSA (NIST FIPS 204, Module-LWE) and Falcon (NTRU lattices). Wallets use it by default.

NIST security level
3 (ML-DSA-65) and 5 (Falcon-1024)
Public key
3,745 bytes
Signature
Up to 4,775 bytes
Used for
Transactions and spend policies, PoWit witness keys, node identity and signed messages
SUITE 0x0003OPTIONAL · CONSERVATIVE

SLH-DSA-128s + Falcon-1024

A hash-based scheme, SLH-DSA-SHAKE-128s (NIST FIPS 205, secure as long as SHAKE256 is), paired with Falcon. A forgery needs a break of a hash function and of a lattice problem.

NIST security level
1 (SLH-DSA-128s) and 5 (Falcon-1024)
Public key
1,829 bytes
Signature
Up to 9,322 bytes, about 7× slower to verify
Used for
Transaction signatures only: key addresses and spend-policy keys, valid from the genesis block

How the halves are bound. Each half signs its own message, which names the suite and the half and carries the transaction's signature hash. A key of one suite never verifies a signature of another, and a signature with one half removed never verifies. Wallet support. The command-line wallet creates keys of either suite; the browser wallet, PQ-PSBT and descriptors use the default suite for now. Legacy. ML-DSA-65 alone (suite 0x0002) stays valid only so that outputs locked to such keys remain spendable. It is non-standard, and wallets never sign with it.

06 / THE NEW CHAPTER

The evolution,
made clear.

What changes with Obenblock, and what carries over from the GnB base.

Is Obenblock GnB's new name?

The GnB repository was renamed ObenBlock, keeping its history. The design also plans a new chain, with a new genesis, the OBB ticker and SHA-256d mining. The relaunch does not change the existing GnB network.

Do SHA-256d and PoWit do the same thing?

They serve different functions. SHA-256d is the proof of work used to mine blocks. PoWit is the finality layer: witnesses vote with weight earned from work shares, using keys that evolve each epoch.

Which post-quantum signatures does Obenblock use?

By default, ML-DSA-65 + Falcon-1024: every signature carries both, and both must verify. For transaction signatures, a holder can choose the conservative suite instead, SLH-DSA-128s + Falcon-1024, which adds a hash-based guarantee at about twice the signature size. Witness keys, node identities and signed messages always use the default suite. SHA-256d is the mining hash, not a signature.

Are my GnB and Bloch keys still valid?

The specification plans to open the same keystores and normalize compatible addresses to obb1…. Control stays with the same keys, but GnB balance history is not transferred. The carry-over uses the Bloch Genesis-3 snapshot, as in the GnB genesis.

Is Obenblock live yet?

The specification consulted, dated October 17, 2026, identifies the relaunch as a project in development. This page presents that planned architecture. Follow the implementation and launch instructions in the official repository.
