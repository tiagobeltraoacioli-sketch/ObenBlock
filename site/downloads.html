Binaries at launch.

ObenBlock's release binaries are published at launch, together with their checksums, the genesis block hash and the DNS seed. Nothing is published yet: there is no ObenBlock network to join before then. The code base is open and builds from source today.

01 / RELEASE

Three binaries.

64-bit Linux and macOS. Each release lists its files with SHA-256 checksums.

NODEAT LAUNCH

obenblock

The full node: validates SHA-256d blocks and PoWit finality, relays on port 18110 and serves RPC on 18210 (bound to localhost by default).

COMMAND LINEAT LAUNCH

obenblock-cli

The RPC client and keystore tool: create a wallet of either signature suite, send, and read the node's finality with getfinalityinfo.

WALLETAT LAUNCH

obenblock-wallet

The keystore wallet: addresses, public keys, signing and payments against a node's RPC.

02 / FROM SOURCE

Build it yourself.

The Rust toolchain is pinned by rust-toolchain.toml; cargo installs it on first use.

OBENBLOCK / BUILD
git clone https://github.com/gnb-smh/ObenBlock.git
cd ObenBlock
cargo build --release

Before the relaunch packages land, this build produces the GnB tools (gnb, gnb-cli, gnb-wallet in target/release) and runs the GnB chain. The ObenBlock names, chain ids and genesis come with the packages listed in the relaunch plan.

Regtest (chain id 0x4F420002, obb1t… addresses) is the network for local development and tests. How to start it is documented with the release.

Running a node: requirements, ports and operation are described in docs/RUNNING.md, which is updated for ObenBlock with the release.

03 / YOUR KEYS

Bring the keystore you have.

The browser wallet and explorer run on this site, against this site's node API.

KEYSTORESGNB · BLOCH

Same file, same key

A GnB keystore (v2 or v3) or the Bloch JSON keystore opens unchanged. Its gnb1… or bloch1… address is shown as the obb1… address of the same script.

BROWSERWALLET

Keys are decrypted and used only in your browser tab, inside WebAssembly. Nothing secret is sent anywhere.
