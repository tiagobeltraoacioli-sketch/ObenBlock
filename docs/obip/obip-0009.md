  Type: Standards Track

## Abstract

Today every ObenBlock full node downloads every block in full. Witness
shares (DESIGN-obenblock.md §6.1) prove that the share's job server held
the attested block's data, but not that the data was published to anyone
else. This OBIP proposes data availability sampling (DAS). Each block
commits, in its coinbase, to a two-dimensional Reed-Solomon extension of its
transaction data, with hash-based Merkle roots. Full nodes recompute the
commitment and reject blocks whose commitment is wrong. Light nodes, and
witnesses that do not download whole blocks, sample random chunks with
Merkle proofs. They accept a block as available only when every sample
answers. Bad encodings are shown to light nodes by hash-based fraud proofs.
The commitment is a soft fork. Sampling and chunk relay are peer services.
PoCI votes do not change. The OBIP gives the detection probabilities and
the assumptions they need. It does not fix production parameters, and it
does not claim that availability is solved.

## Motivation

- The technical note "Votos sobre shares, provas compactas e finalidade
  segura" (p. 10–11) separates three checks that are often confused:
  - validity (the whole block follows the rules);
  - availability (the data can be rebuilt by others);
  - finality (one history is chosen).
  A quorum of signatures does not make data available, and a validity
  proof does not either: "a validity proof does not solve data
  withholding" (p. 6).
- Sampling transactions is not validation. In a block of 1 million
  transactions, 32 uniform samples miss a single invalid transaction with
  probability about 99.9968 % (note p. 10). DAS answers only "can the data
  be rebuilt", and only under the assumptions below.
- Witness shares sample 8 chunks of 64 bytes per job (DESIGN-obenblock.md
  §6.1). They enforce custody at the job server, which the miner chooses.
  The share's chunk indices come from the job, so they are not a sample
  that a third party controls. A share therefore says nothing about
  whether other nodes can fetch the block.
- At today's `MAX_BLOCK_SIZE` of 1,000,000 bytes (CONSENSUS.md "Block
  size") a full node can download everything, so DAS is not urgent for full
  nodes. It becomes a prerequisite for:
  - light clients that check more than headers and certificates;
  - any later increase of block size;
  - data posted by L2 batches (note p. 18, [R17], [R18]);
  - aggregated certificates carried outside the block body, whose material
    must stay fetchable (note p. 19).

## Specification

Hashes, tags and tree shape follow the tagged-tree convention of
DESIGN-obenblock-poci.md §2, with the tags below.

### Data stream and square

```text
stream(B)  = wire(tx_1) ‖ … ‖ wire(tx_n)        non-coinbase transactions, block order
L          = len(stream(B))
s          = CHUNK_SIZE                           OPEN (512 bytes used in examples)
m          = ceil(L / s)                          zero-padded last chunk
k          = smallest power of two with k × k >= max(m, 1)
original   = k × k chunks, row-major, missing chunks all zero
extended   = 2k × 2k: rows extended, then columns, by a systematic
             Reed-Solomon code of rate 1/2        OPEN: field (GF(2^8) or GF(2^16)),
                                                   evaluation points, exact codec
```

The coinbase is left out of the stream because it carries the commitment.
It travels with the header, as in the base.

### Commitment

```text
leaf(i, j, c)  = tagged("OBB-DAS-v1/leaf", u32le(i) ‖ u32le(j) ‖ c)
row_root_i     = tree_root over leaf(i, 0..2k-1)     tag "OBB-DAS-v1/node"
col_root_j     = tree_root over leaf(0..2k-1, j)
data_root      = tagged("OBB-DAS-v1/root", u32le(k) ‖ u32le(s) ‖ u64le(L)
                        ‖ tree_root(row_root_0 … row_root_{2k-1}
                                    ‖ col_root_0 … col_root_{2k-1}))
```

From the activation height, the coinbase `script_sig` carries, right after
the 80-byte commitment of CONSENSUS.md "Coinbase commitment":

```text
offset size field
80      8   "OBB-DA01"
88     32   data_root
```

OPEN: a common layout for tagged OBIP fields in the coinbase miner bytes
(OBIP-9 `OBB-DA01`, OBIP-10 `OBB-SC01`, and pool tags read by OBIP-11),
so that both fields can be present; the offsets shown assume this field
is the only one.

A block without this field, or with a `data_root` that differs from the one
recomputed from its transactions, is invalid. This only restricts miner
bytes that were free before, so it is a soft fork. The block id covers it
through the coinbase txid.

### Peer messages

| Message | Content |
|---|---|
| `getdasroots` | `block_id[32]` |
| `dasroots` | `block_id ‖ u32le(k) ‖ u32le(s) ‖ u64le(L) ‖ 4k × root[32]` (checked against `data_root`) |
| `getdaschunk` | `block_id ‖ u32le(i) ‖ u32le(j)` |
| `daschunk` | `block_id ‖ u32le(i) ‖ u32le(j) ‖ chunk[s] ‖ u8(depth) ‖ depth × sibling[32]` (path to `row_root_i`) |
| `dasfraud` | bad-encoding proof: `block_id ‖ u8(axis) ‖ u32le(index)` and `k` chunks of that row or column with their paths to the other axis's roots |

- A bad-encoding proof is valid when the `k` chunks are proven members, and
  decoding them and re-extending gives a row (or column) whose root differs
  from the committed one. Its size is about `k × (s + 32 × log2(2k))` bytes.
- Rate limits, request privacy and the exact relay policy are OPEN. Request
  privacy matters because of selective disclosure (Security
  Considerations).
- Full nodes serve chunks for blocks above the last finalized checkpoint and
  for `DAS_SERVE_EPOCHS` epochs below it (OPEN).

### Sampling

- A sampler draws `n` distinct pairs `(i, j)` uniformly from the extended
  square with a local CSPRNG. It does not reveal them before asking. It
  asks different peers for different samples.
- The block is **available to that sampler** when all `n` samples return
  with valid paths before a timeout (OPEN). Otherwise the sampler treats the
  block as unavailable, and so treats every descendant as unavailable too.
- A sampler that receives a valid `dasfraud` treats the block as invalid.
- Samplers relay the chunks they received, so that the union of honest
  samples can rebuild the square.

### Use by witnesses (node policy, not consensus)

- A witness that does not hold a block in full samples it before voting.
  The witness duty does not vote for a target whose unfinalized ancestry
  holds a block that is unavailable or proven bad. Such a refusal is never
  evidence and is never punished (base §5, "never punished").
- Attestation messages and certificates are unchanged.
- OPEN: whether a later OBIP should commit sampling results in votes, with
  assignments from a seed that the block producer cannot predict, such as a
  block some heights later. Public assignments let a producer serve exactly
  the assigned chunks, so they cannot replace private sampling.

### Detection, in the independent model

For the 2D code above, the square cannot be rebuilt only if at least
`(k+1)^2` of the `(2k)^2` extended chunks are withheld, a fraction above
1/4. One uniform sample then misses the gap with probability at most 3/4.
For a 1D rate-1/2 code the fraction is above 1/2. Failure to detect, with
replacement, `(1 - f)^n`; without replacement, `C(M - w, n) / C(M, n)`:

| samples `n` | `f = 10 %` | `f = 25 %` (2D threshold) | `f = 50 %` (1D threshold) |
|---|---|---|---|
| 16 | 18.5302 % | 1.0023 % | 1.526 × 10^-5 |
| 32 | 3.4337 % | 1.0045 × 10^-4 | 2.328 × 10^-10 |
| 64 | 0.1179 % | 1.0091 × 10^-8 | 5.421 × 10^-20 |
| for 2^-80 per event | 527 | 193 | 80 |

The 10 % and 50 % columns and the last row's 527 and 80 are from the note
(p. 11). The 25 % column is computed here the same way. These are
per-sampler, per-block numbers in an idealized model. They are not the
probability that the chain accepts unavailable data. The lifetime budget
over all blocks and all samplers is stricter (note p. 11).

Illustrative cost, with every parameter OPEN: a 1 MB block with
`s = 512` gives `m ≈ 1,954` and `k = 64`, so an extended square of
128 × 128 chunks, about 8 MiB. `dasroots` is about 8 kB per block. Each
sample is about `512 + 7 × 32 = 736` bytes. 193 samples are about 142 kB
per block, about 4.7 kB/s at 30-second blocks, per sampler. Full nodes
store or recompute the extension.

## Rationale

- **2D over 1D.** A 1D code needs fewer samples (the threshold is above
  1/2), but a bad-encoding proof must carry half of the whole extended data.
  In 2D a proof carries one row or column, `O(sqrt(m))` chunks, at the cost
  of a lower threshold (1/4) and more samples (Al-Bassam, Sonnino and
  Buterin, [R17]).
- **Hash-based commitments and fraud proofs.** KZG polynomial commitments
  make encoding correctness provable without fraud proofs, but they are
  pairing-based, so they are not post-quantum and need a trusted setup.
  ObenBlock's PQ goal rules them out as the base mechanism. Hash-based
  proofs of proximity (FRI-style, STARK family) are a PQ-plausible
  alternative. Their proofs are tens to hundreds of kB, and no ObenBlock
  circuit has been built. OPEN for a later OBIP.
- **Full nodes recompute.** A wrong `data_root` is a plain validity failure
  for anyone who holds the data, so a full node never needs a fraud proof.
  Fraud proofs exist only for samplers.
- **Votes unchanged.** Adding sampling to the finality rules would make
  finality depend on a statistical check. The base rejects this for
  committee sampling (note p. 8), and accountability would suffer. Keeping
  DAS as a precondition for honest voting gives the property without a new
  vote format.
- **Rejected: rely on witness shares.** See Motivation. The miner chooses
  the share sample, and it proves custody, not publication.
- **Rejected: merged mining or self-anchoring as availability.** An anchor
  or a merged-mined header commits to a hash and says nothing about who can
  fetch the data.
- **Rejected: blind voting / receipt-free voting to protect samplers.**
  Hiding voters adds complexity. Request privacy at the network layer
  protects the sample instead, and votes stay attributable (note p. 18).

## Backwards Compatibility

The commitment is a soft fork. Nodes that do not upgrade still accept
upgraded blocks, because the field sits in free coinbase bytes. They do not
enforce it. Activation is a coordinated ObenBlock release height. Miners and
`getblocktemplate` must fill the field from that height. Stratum jobs are
unchanged, because the coinbase is already miner-built. Peer messages are
new and optional: old peers ignore them. GnB is unaffected.

## Security Considerations

- **The numbers need these assumptions** (note p. 11). Samples are
  independent and uniform, and the producer does not know them in advance.
  Enough honest samplers exist, and their union covers the square well
  enough to rebuild it. At least one honest full node watches and relays
  fraud proofs to every sampler (an eclipsed sampler gets none). The
  number of honest samplers needed is OPEN.
- **Selective disclosure.** A producer can answer only some requesters, or
  only until the samplers are satisfied, and then hide the rest from anyone
  trying to rebuild. Without request privacy and gossip of chunks, the
  per-sampler bound does not translate into availability for the network.
- **Duplicated work.** A thousand identities sampling the same chunk are
  one sample. Coverage must count distinct indices. Quorum weight is
  unrelated to coverage and must not be inferred from it (note p. 11).
- **Availability is not validity.** DAS does not show that transactions are
  valid. A light node still needs full validation or a validity proof, and
  PoCI finality for ordering.
- **Retention.** Availability at publication is not availability forever.
  `DAS_SERVE_EPOCHS` and archival are OPEN.
- **DoS.** Recomputing the extension costs full nodes CPU and memory per
  block. Chunk serving and fraud-proof checking must be rate-limited before
  any signature or decode work.
- **Post-quantum status.** The construction uses only hashes (SHA-256d and
  tagged trees), which are considered quantum-resistant at these output
  sizes, with Grover's quadratic speed-up. Pairing-based alternatives (KZG,
  BLS, Groth16) are **not** post-quantum. STARK-style proofs of encoding are
  tens to hundreds of kB. For scale, one hybrid ML-DSA-65 + Falcon-1024
  signature is about 4.6 kB.

## Deployment prerequisites

- Choices for `CHUNK_SIZE`, field and codec, the sampling count `n`,
  timeouts, `DAS_SERVE_EPOCHS` and the minimum number of honest samplers,
  backed by a measured prototype.
- A reference model of the square, roots and fraud proofs, with vectors.
- A network simulation with selective disclosure, eclipse and partial
  reconstruction (note p. 21: "withheld data, false encoding, repeated
  samples").
- A measurement of full-node cost at `MAX_BLOCK_SIZE`.
